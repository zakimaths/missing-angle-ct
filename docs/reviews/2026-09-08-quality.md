# Accessibility, security and design review

Reviewed 8 September 2026. Scope: the shared live reconstruction interface, GitHub Pages demo, Mac embedding and file imports. The existing white, ink and teal design and formal explanatory language were retained.

## Result

The interface follows a coherent scientific-workstation design. Eight verified issues were fixed across navigation, accessible data, replay state, recovery, memory use, import validation and browser security policy. No blocking issue remains in the tested flows. This is a scoped engineering review, not a WCAG conformance certificate or a penetration test.

| Dimension | Score (0–4) | Evidence and remaining limits |
| --- | ---: | --- |
| Accessibility | 3 | Automated axe checks, keyboard operation, labelled controls, visible focus and numeric alternatives. A complete VoiceOver assessment remains outstanding. |
| Performance | 3 | Calculation stays in a worker. Refinement retains one image per pass; the Mac app still embeds the bundled datasets to support offline use. |
| Responsive design | 3 | Desktop and 327 CSS-pixel reflow verified. Wide numerical tables scroll within their own labelled regions. No device-wide touch or browser matrix was run. |
| Theming | 3 | Existing light theme retained; text contrast checked automatically. Literal scientific and status colours remain, and the design metadata predates the current interface. |
| Implementation integrity | 3 | Measurements, source images, reconstruction and assessment remain separate. Replay counters now describe the displayed frame. Documentation metadata still needs a separate refresh. |
| **Total** | **15/20** | **Good, with stated verification limits** |

## Fixed findings

| Priority | Finding | Change and verification |
| --- | --- | --- |
| P1 | Compressed MATLAB input had only a compressed-file size limit. | Added a 32 MB expanded limit before SciPy, bounded dimensions, payload sizes, field counts and nesting. Reject unsupported objects, functions, sparse arrays and malformed elements. Compression-bomb, forged-dimension and short-payload tests verify rejection. All three original Helsinki files still produce the same measurements. |
| P1 | Detector profiles were available primarily as canvas graphics. | Added a keyboard-accessible table with a caption, column headers and all readings for the inspected view. The view slider has a meaningful spoken angle and view number. WCAG 1.1.1 and 1.3.1 considerations. |
| P2 | A long introduction and repeated explanations delayed access to controls. | Added section links and a first-focusable skip link. Kept the full workflow explanation in a disclosure. The skip link moves focus to the controls. WCAG 2.4.1 consideration. |
| P2 | Replay showed the final view count while displaying an early frame. | Derive the diagram count from the displayed calculation step. Verified that frame one reads 1 / 90 and the slider describes that same frame. |
| P2 | Worker failure could leave actions enabled for an incomplete result. | Failed runs clear the exportable result, disable refinement and export, retain partial playback, and focus a recovery message. |
| P2 | Repeated refinement stored many intermediate pixel buffers. | Retain every first-pass view, then one image per completed refinement pass. Numerical updates and progress reporting are unchanged. At the maximum supported grid and view count, frame pixel buffers are below 95 MiB even after all 12 six-pass stages; other working memory is additional. A worker test compares the final values against independent iteration of the same numerical kernel. |
| P2 | The static demo had no explicit content security policy. | Added a same-origin policy for scripts, styles and data, with limited data/blob image and worker support. Object loading, form submission and base-URL changes are disabled. No inline script or unsafe-eval permission is required. Added a referrer policy. |
| P2 | Some controls lacked descriptive state or consistent interaction targets. | Added spoken replay descriptions, associated import errors, required region-name state, explicit focus handling, 44-pixel range/disclosure targets and narrow-layout constraints. The Mac document now has a title and main landmark. |

## Verification

- **77 Python tests passed**, including existing ZIP, source-integrity, reconstruction and replay checks and five new MATLAB security/compatibility tests.
- **18 JavaScript tests passed**, including measured objects, real-body simulations, analytic references, deterministic reconstruction, worker control and bounded refinement history.
- Ruff checks passed.
- Original HTC object A, B and C MATLAB imports matched the bundled projection values to the existing eight-decimal rounding tolerance.
- axe-core **4.13.0**, obtained from its official npm package and verified against its SHA-512 package integrity, was run on a temporary local copy of the demo. The initial interface passed 48 automated rules and the populated reconstruction, enhancement, annotation and detector-table state passed 54, with zero violations and zero incomplete results in those runs. The audit tooling is not shipped.
- Desktop and narrow-screen checks covered the initial interface and a body reconstruction with enhancement, references and labels. Canvas numerical data, focus destinations, slider descriptions, reference errors and view counters were checked separately from automated rules.
- Dependency audit: **52 third-party packages checked, no published vulnerabilities reported** by pip-audit at review time. The local application package is not published on PyPI and was reviewed as source instead. An advisory scan cannot establish absence of undisclosed vulnerabilities.

## Existing safeguards retained

Projection and reference imports have byte, dimension and finite-value limits. Imported names and region labels are rendered through text nodes, not HTML insertion. ZIP experiment imports check allowed members, duplicates, expanded size, array headers, exact shapes, types and checksums, with pickle disabled. No ZIP entries are extracted to user-selected paths. The local server binds to loopback, and telemetry is disabled. Imported files are processed locally; the static demo has no upload service.

## Design detector review

The mechanical design detector was run once on the changed web files. It reported palette/type documentation advisories and six image tags whose sources are assigned during loading. The image findings are false positives: the result container remains hidden until real images load, and the loaded images were inspected. Scientific grayscale, error colours and status colours are intentional. The existing design sidecar is stale; updating the design documentation and its generated metadata is a separate maintenance task, not a reason to alter valid scientific colours.

## Remaining limits and follow-up

- Perform a dedicated VoiceOver pass and testing with users who rely on assistive technology. Automated success does not establish equivalent interpretation of every spatial CT feature.
- GitHub Pages does not provide project-level control of arbitrary HTTP response headers. The metadata policy does not supply a response-header `frame-ancestors` policy; the local embedded app uses Streamlit's framework security boundary rather than the static page's script policy.
- The MATLAB parser intentionally supports the bounded numeric, string, cell and structure subset needed for HTC v5 files. General MATLAB objects, v7.3/HDF5 files and arbitrary hospital formats remain unsupported.
- Refresh the design reference and sidecar separately if they will be used for future interface generation. No redesign or dark theme was introduced in this pass.
